# LSL Logistics Network — Corporate Logistics Website

## 1. Project Description
A premium, modern B2B corporate logistics & freight-forwarding website for **LSL Logistics Network (OPC) Pvt. Ltd.** The site presents LSL as a reliable, technology-driven end-to-end supply-chain partner serving businesses across India and global markets. Built for trust, professionalism, speed, transparency and conversion.

## 2. Page Structure
- `/` — Home (hero, tracking widget, company intro, services grid, why-LSL, global map, process, quote CTA)
- `/about-us` — About the company
- `/services` — Services overview grid
- `/services/:slug` — Individual service detail (11 services)
- `/track-order` — Shipment tracking via **AWB (Air Waybill) number** (no login). Order ID is internal/admin-only.
- `/contact` — Contact + Get a Quote form

## 4. Data Model Design (Database-driven — Readdy Backend)
Persistent tables live in Readdy Backend. Tables:

`shipments` — one row per shipment request / Order ID:
| Field | Type | Description |
|-------|------|-------------|
| id | text PK | Unique Order ID (e.g. LSL202600123) |
| status | text | Current shipment status (default `Order Received`) |
| service_slug | text | Service slug (ocean-freight-forwarding, etc.) |
| service_type | text | Human-readable service label |
| customer_name / company_name / email / phone | text | Contact details |
| origin / destination | text | Key points of movement |
| cargo_type / weight / shipment_date | text | Shipment metadata |
| current_location | text | Current position |
| estimated_delivery | text | ETA |
| last_updated | timestamptz | Last status update time |
| shipment_details | jsonb | Service-specific form fields |
| created_at / updated_at | timestamptz | Audit |

`shipment_events` — append-only event history per shipment:
| Field | Type | Description |
|-------|------|-------------|
| id | bigserial | Event id |
| shipment_id | text FK -> shipments.id | Parent shipment |
| status | text | Event status |
| note | text | Description |
| location | text | Where applicable |
| event_time | timestamptz | When it happened |

RLS: anon `SELECT` on both tables (public tracking + lookup). Writes are handled by the
`create-shipment` edge function (service role) which generates a unique Order ID and writes the
initial `Order Received` event. Future admin updates go through the backend management UI.

## 5. Backend / Third-party Integration Plan
- Database: **Readdy Backend connected**. All shipment/tracking data is now persistent
  (`shipments` + `shipment_events`). Order ID is generated by the `create-shipment` edge function.
- Order tracking: DB-driven, Order ID only (no login/OTP/email/phone).
- Service requests: every service detail page has a `Request This Service` form that inserts a
  shipment and returns the generated Order ID for tracking.
- Forms: Contact/Quote uses built-in Form capability.
- Payments / Shopify / Stripe: Not required for this project.
